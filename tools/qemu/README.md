# A model of the NVIDIA register interface

`sapote_nvidia_model.c` is a QEMU device that puts PCI vendor `0x10DE` on the
bus with the registers, apertures and capabilities Sapote's ten NVIDIA drivers
read. It exists
because no emulator models an NVIDIA part and because those drivers would
otherwise be code that has never executed.

**It is not an NVIDIA GPU and it does not emulate one.** There is no graphics
engine, no channel, no display, no interrupt and no memory management in it.
Nothing it does should be read as a description of real hardware beyond the
five registers it answers.

## The circularity, stated plainly

The register *offsets* in this file and in `src/kernel/nvidia.c` come from the
same reading of the same public documentation. A mistake in that reading would
appear identically in both, and this model would happily confirm it. That is
inherent to a model and is exactly why it is not a substitute for silicon.

What the model deliberately does **not** decide is the *values*:

| Value | Where it comes from |
| --- | --- |
| `PMC_BOOT_0` | a command-line property, pinned by the caller |
| the board straps | a command-line property |
| the engine enable mask | a command-line property |
| the subsystem identity | a command-line property, written into real config space |
| the ROM image | a file, generated by `tools/nvidia_vbios_image.py` |
| the configuration mirror | QEMU's own `pci_default_read_config` |
| the PCI Express link | QEMU's own `pcie_endpoint_cap_init` |
| the aperture shape | QEMU's own BAR registration |
| the timer | QEMU's `QEMU_CLOCK_VIRTUAL` |

So a driver checked against this model is checked against values pinned outside
both the driver and the model, and its "the two configuration paths agree" and
"the counter advances" checks are real rather than staged.

## Building

QEMU 8.2.2 is the version Sapote's own scenarios are verified on; 9.1.0 also
works. Building 9.1 is what first exposed the RF handling described in
`docs/NVIDIA.md`, and the model runs on either.

```sh
git clone --depth 1 --branch v8.2.2 https://github.com/qemu/qemu.git
cp tools/qemu/sapote_nvidia_model.c qemu/hw/misc/
printf "%s\n" "system_ss.add(when: 'CONFIG_PCI', if_true: files('sapote_nvidia_model.c'))" \
    >> qemu/hw/misc/meson.build
cd qemu && ./configure --target-list=x86_64-softmmu --disable-docs --disable-tools
ninja -C build qemu-system-x86_64
```

## Running

```sh
python3 tools/nvidia_vbios_image.py --write /tmp/reference-vbios.rom
qemu/build/qemu-system-x86_64 -machine q35,accel=tcg -m 128M -smp 1 \
    -display none -monitor none -serial stdio -no-reboot \
    -device isa-debug-exit,iobase=0xf4,iosize=0x04 \
    -cdrom <sapote.iso with sapote.test=nvidia> -vga std \
    -device sapote-nvidia-model,boot0=0x164000A1,straps=0x0000042C,\
        subsystem=0x87651043,vbios=/tmp/reference-vbios.rom
```

A passing run exits 233 and prints `ST PASS nvidia`. The results, and the two
controls that prove the run is not vacuous, are in [`../../docs/NVIDIA.md`](../../docs/NVIDIA.md).
